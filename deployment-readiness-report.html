Critical deployment blockers

Critical

1. The deployed application will call localhost

Evidence: Both src/environments/environment.ts and src/environments/environment.prod.ts contain:

apiBaseUrl: 'http://localhost:32769/api'

Impact: In production, localhost means the visitor's own computer. Authentication, flight search, user accounts, leads, and other API calls will fail.

Required fix: Deploy the backend publicly and configure the production frontend with its public API URL, for example https://api.example.com/api. Do not commit secrets to Angular environment files; frontend values are visible to users.

Critical

2. HTTP API requests will be blocked from an HTTPS site

Evidence: The configured API URL starts with http://. Vercel and Netlify serve production sites over HTTPS.

Impact: Modern browsers block active mixed content, so API calls will fail even if the IP address or hostname is reachable.

Required fix: Give the backend a valid TLS certificate and expose it through an https:// URL. Also configure backend CORS to allow the final frontend domain and preview domains as appropriate.

Configuration warnings

Warning

3. Client-side routes need an SPA fallback

The application has routes such as /search, /booking, /passengers, /account, and /auth/login.

Impact: Opening or refreshing these URLs directly can return a platform 404 unless all paths are rewritten to /index.html.

Required fix: Add a Vercel rewrite in vercel.json or a Netlify rewrite in netlify.toml/_redirects.

Warning

4. Production environment configuration is incorrect

environment.prod.ts sets production: false and is currently identical to the development environment. The Angular build configuration also has no explicit fileReplacements entry.

Required fix: Set the production flag correctly and configure a reliable production API URL strategy. Confirm which environment file Angular 20 uses during the production build.

Warning

5. Production bundle budgets may fail the build

The production limits are 1MB for the initial bundle and 8kB for any component stylesheet.

Impact: If compiled output exceeds either maximum, npm run build will fail and stop deployment.

Required fix: Run a clean production build locally or in CI. Optimize oversized bundles/styles instead of increasing budgets unless the larger size is intentional and reviewed.

Developer completion checklist

  1. Deploy the backend at a public HTTPS URL.
  2. Update the production API base URL and set production: true.
  3. Configure backend CORS for the production and permitted preview domains.
  4. Add an SPA rewrite so every application route serves index.html.
  5. Pin a supported Node.js version.
  6. Run npm ci followed by npm run build and resolve all compilation or budget errors.
  7. Test login, registration, account, search, booking, passengers, direct route refreshes, and API error handling on a preview deployment.
  8. Optimize the two largest images and remove the Windows shortcut file.
